# Releasing

Maintainer checklist for cutting a new release of the `koin` plugin.

The plugin is the repo root: `/plugin marketplace add`, `claude --plugin-dir` and the
Anthropic directory all read the committed `skills/` on `main`, generated by `./build.sh`
from `src/`. A release is a version bump on `main` + a tag + a GitHub Release.

## Before tagging

- [ ] All intended changes merged into `main`
- [ ] `./build.sh` succeeds locally (validates both `plugin.json` and `marketplace.json`, and that plugin names are consistent across the two) and leaves `git status` clean — `skills/` committed up to date with `src/`
- [ ] Local smoke test passes: `claude --plugin-dir .` and run one trigger prompt per skill you changed
- [ ] Marketplace install flow still works from a fresh Claude Code session:
      `/plugin marketplace add InsertKoinIO/koin-skills` then
      `/plugin install koin@koin-skills` — each installed skill has its `references/`
- [ ] The eval suite (private `kotzilla-io/koin-skills-evals` repo) runs end-to-end for the skills you changed
- [ ] No uncommitted changes (`git status` clean)

## Version bump

- [ ] Bump `version` in `.claude-plugin/plugin.json` following semver:
  - **MAJOR** — breaking changes to SKILL.md workflow, removed references, incompatible file layout
  - **MINOR** — new migration path, new feature, new reference
  - **PATCH** — fixes, wording, typo, clarifications
- [ ] Add a matching `## [X.Y.Z] - YYYY-MM-DD` section to `CHANGELOG.md` listing user-visible changes
- [ ] Commit: `chore: release vX.Y.Z`

## Publish the release

- [ ] Run `./release.sh` — it rebuilds and refuses to release if `skills/` is out of date, then tags `vX.Y.Z`, pushes the tag, and creates a GitHub Release with the `.skill` bundles and `koin-plugin.zip` attached
- [ ] Verify the release page shows both assets and the notes rendered from `CHANGELOG.md`

## After release

- [ ] Anthropic directory: the listing tracks `main` (plugin path = repo root) — run "Check for new commits" (or wait for the schedule / push webhook) and publish the new version
- [ ] Re-test install from the published directory entry
- [ ] Announce in Koin channels (Slack, Twitter/X, release notes mailing) — optional for PATCH
- [ ] First-time directory submission: https://claude.com/docs/plugins/submit — repository `InsertKoinIO/koin-skills`, tracked branch `main`, plugin path = root (repository and path can't be changed later)

## Rolling back

If a release is bad:

- [ ] `gh release delete vX.Y.Z --cleanup-tag` to remove the release and tag
- [ ] Revert the offending commits
- [ ] Cut a PATCH release with the fix

Do **not** force-push over a published tag — consumers may have cached the bundle.
